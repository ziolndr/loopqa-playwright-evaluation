# LoopQA — data-driven Playwright evaluation

JavaScript (ESM) + Playwright automated acceptance suite for the [Asana-like demo app](https://create-asana-like-pr-39y5.bolt.host/). Covers all **six** required scenarios across the **Web Application** and **Mobile Application** Kanban boards.

## One-command macOS setup, validation and publication

Download **`LOOPQA_ONE_COMMAND.command`**, then run this **single command** in Terminal:

```bash
bash "$HOME/Downloads/LOOPQA_ONE_COMMAND.command"
```

The launcher contains the entire project, unpacks it into `~/Projects/loopqa-playwright-evaluation`, installs Node.js and GitHub CLI with Homebrew only if missing, installs Playwright and Chromium, runs scenario-data checks and all six live browser tests, and publishes to **`ziolndr/loopqa-playwright-evaluation`** if they pass. The publisher reuses the established GitHub CLI login and existing `ziolndr` SSH key; it will not switch Git pushes to HTTPS. If GitHub CLI is unauthenticated, it requests sign-in once for repository creation. It verifies the account, uses SSH to push GitHub Actions files, and refuses to overwrite unrelated repositories. It does not upload the recruiter-requested walkthrough video or submit the Google Form.

Requires macOS, internet access, and Homebrew if either Node.js or GitHub CLI is not already installed. Node.js 20+ is required. Existing project folders are preserved. The repair launcher updates only the test's Board Page Object, its test invocation, documentation, and publishing scripts; original copies of replaced files are backed up under `.loopqa-backups/` before replacement.

### Alternative: project ZIP

For a standard extracted project, download the ZIP and paste **one command**:

```bash
cd "$HOME/Downloads" && unzip -oq loopqa-playwright-evaluation.zip && cd loopqa-playwright-evaluation && bash scripts/setup-and-publish.sh
```

To run tests without publishing:

```bash
npm install
npx playwright install chromium
npm test
```

For step-by-step browser playback: `npm run test:headed`. For the interactive debugger: `npm run test:ui`. For an HTML report after execution: `npm run report`.

## Design

- `data/scenarios.json` — **single source of truth**: project, column, task title, and expected tags for all six cases.
- `tests/board.spec.js` — loops over JSON, registering six independent Playwright tests. Each follows the same login, navigation, and assertion path.
- `pages/LoginPage.js` — UI login with `admin` / `password123` (environment-overridable), then verifies the login form is gone and authenticated board navigation is visible.
- `pages/BoardPage.js` — reusable navigation, column scoping, task-card scoping, and exact tag assertions. A tag elsewhere on the board cannot satisfy an assertion on the target card.
- `tests/scenarios.test.mjs` — fast, dependency-free JSON contract checks.
- `.github/workflows/playwright.yml` — GitHub Actions Chromium execution, reporting, screenshot/trace/video artifacts on failure.

### Configuration

Use the public demo credentials supplied in the evaluation. For overrides:

```bash
DEMO_USERNAME=admin DEMO_PASSWORD=password123 npm test
```

`DEMO_BASE_URL` can point at a separately hosted test environment. CI supports optional `DEMO_USERNAME`, `DEMO_PASSWORD` repository secrets and `DEMO_BASE_URL` repository variable.

## Reporting and reliability

The tests use built-in Playwright auto-waiting assertions rather than fixed delays. Each scenario is isolated in its own browser context and performs its own UI login. The runner uses Chromium; CI retries once and saves an HTML report and JUnit results. Playwright records a screenshot, trace, and video **only on failed tests**. The separate recruiter-requested walkthrough video is not generated by the test suite.

### Validation status

Syntax and scenario-data checks are independently runnable with `npm run typecheck && npm run test:data`. **Passing these checks is not a substitute for executing the browser tests against the live demo URL.** On October 13, 2026, the initial six live browser tests failed because the previous implementation required an exact `To Do` text node immediately after clicking the project. The repair instead verifies that the requested task becomes visible, then scopes the task under a flexible column heading (case-insensitive and permitting a task count) while excluding other columns. The live site was unreachable from the packaging environment, so this fix has **not** been live-verified. If the application layout still differs, the failure now prints its URL, headings, sidebar, and rendered page text in the test error; failure screenshots/traces are also saved. Do not submit until all six browser tests pass.

## Submission

1. Run the one-command launcher, which executes all checks and publishes a **public** repository at `https://github.com/ziolndr/loopqa-playwright-evaluation` only after the live tests pass. Or use `./scripts/publish-github.sh` from an already validated project.
2. Check the six browser tests and HTML report.
3. Record a separate 2–3 minute walkthrough explaining the JSON-driven matrix, Page Objects, task-card-scoped assertions, and run output.
4. Enter the public repository URL and upload the walkthrough video at the evaluation [Google Form](https://forms.gle/vo7Y7dXtnk7F38mp8).
